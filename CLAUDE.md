# home-lab — quick map

Dense index so you can jump straight to files. Conventions and rationale
live in `.claude/CLAUDE.md`. The README is the human-facing guide.

## Stack (verified against package.json)

Node server on `node:http` (no framework, no runtime dependencies) ·
TypeScript **5.9** (tests only) · Vitest **3** · Node **20.12+**. The React
web page was removed 2026-11-26: the native apps in `ios/` replaced it.

## Commands

- Run: `npm start` → http://127.0.0.1:4180 (sample data unless `DATA_SOURCE=live`)
- `npm run typecheck` · `npm test`

## Where things are

- **Metrics page:** `GET /` = `server/metrics-page.mjs metricsPage(snapshot)`: plain HTML, no scripts, reloads every 15 s; services, graphics card, memory, disks, running jobs (Dylan 2026-11-26: "the bare URL can just show backend metrics"). Any other non-API path is a 404.
- **API:** `server/app.mjs` — `GET /api/snapshot` (one build shared by every caller for 3 s, `sharedSnapshot`; any POST makes the next one fresh), `POST /api/actions/:name`
  (`ollama-unload`, `ollama-load`; needs header `x-home-lab: 1`; one at a time, 409 otherwise),
  `POST /api/jarvis/ask` (`{text}`, same header; forwards `Tailscale-User-Login` to Jarvis `/ask`),
  `POST /api/jarvis/chat` (`{text, images?, replyTo?}`, same header; `images` = up to 4 photos `{media_type, data}` base64 for the apps' chat, `parseChatImages`, history turns carry `images: n` and Jarvis's `id`; `replyTo` = the turn `id` of one earlier message this one replies to (Dylan 2026-11-27; `parseReplyTo` in `server/sources/history.mjs`, 400 when it isn't a turn id; sent to Jarvis as `reply_to`, who reads that message alongside the new one), and the history turn then carries `replyTo: {id, role: user|jarvis, text}` (the first 300 characters, for the quote above the bubble); a turn whose `model` is `notice:<source>` is a message he sent unasked (reminder, Lookout, start of day), and its `writer` is the model that wrote it; a `meal_question` event (`key`, `choices`) is answered with `POST /api/jarvis/chat/meal` `{key, choice: same|leftovers|new}` → Jarvis `/chat/meal`; streams Jarvis `/chat/stream` NDJSON; if the phone drops it, the server reads on and the app catches up from history), `GET /api/jarvis/history` (Jarvis `/chat/history`; a page at a time for the apps: `?limit=` 1-100 (default 50), plus at most one of `?before=<turn id>` = the turns just older or `?around=<turn id>` = a window centred on it; answers `{turns, hasMore, hasNewer, pending}` oldest first, `pending` = he's still writing the newest reply; checks and clean-up in `server/sources/history.mjs`, 400 on a bad ask; the chat stream says `{type: 'turn', id}` first = his number for the message just sent; a message sent while he's still answering steers him (Dylan 2026-11-21): its stream answers `{type: 'steered', into, as: steered|stopped|approval}` (the reply goes on in the first stream) or `{type: 'queued', after}` (its own reply follows when the first ends), and when the asker's connection closes before the reply is done the server tells Jarvis with `POST /chat/left` `{turn_id}` (`chatLeft`) so he pushes the reply to the phone; while Jarvis restarts (502/503/504) messages read "Jarvis is restarting. Try again in a moment." via `jarvisSaid` and a chat message is sent once more after 2.5 s), `POST /api/jarvis/warm` (same header; Jarvis `/chat/warm`, sent when the chat sheet opens),
  `POST /api/jarvis/sleep` (`{asleep, source?}`, same header + Tailscale login; Jarvis `/sleep`; the Apple TV's Night button says you've gone to bed, Jarvis marks you up again when you next talk to him),
  `POST /api/jarvis/approve` (`{id, ok}`, same header; Jarvis `/approve`; 410 `{ok: false, gone: true, message, answer?: {ok, by, later}}` when that request is already over, so every screen drops its card for good) + `GET /api/jarvis/approvals` (Jarvis `/approvals`): Approve/Deny cards for `approval`/`approval_done` events on the chat stream and talk line (`later: true` = he said "wait"; self-change tools `change_code`/`apply_code_change`/`change_setting`),
  `POST /api/jarvis/feedback` (`{question, answer, note}`, same header + Tailscale login; Jarvis `/feedback`; Jarvis turns flags into a fix + eval case overnight),
  `POST /api/jarvis/offers/hide` (`{id}`, same header; Jarvis `/offers/{id}/hide`) + snapshot `offers` (Jarvis `GET /offers`, `server/sources/offers.mjs`): a greeting plus offers he can Hide or Start (= chat with `offerId`),
  `POST /api/jarvis/notices/clear` (`{ids}` or `{all: true}`, same header; Jarvis `/notices/clear`) + snapshot `notices` (Jarvis `GET /notices`, `server/sources/notices.mjs`: unread notifications `{id, kind: need|heads|fyi, title, body, source, created, approvalId?, turnId?}` (`body` up to 3000 characters, the whole message, Dylan 2026-11-21) (`turnId` = the history turn `id` holding the full message, so a tap opens the chat there; `kept: true` once he chose to keep it, with `source: kept` for a kept chat message); `POST /api/jarvis/notices/keep` (`{turnId}` = a chat message or `{id}` = a notice, same header; Jarvis `/notices/keep` with `turn_id`/`notice_id`; answers `{ok, message, notice?}`) + `POST /api/jarvis/notices/unkeep` (`{id}`; Jarvis `/notices/unkeep`): a kept one is a yellow dot in the apps and stays through Clear and Clear all until he lets it go, and its history turn carries `kept: true` (Dylan 2026-11-19; `parseKeep`/`parseUnkeep`); the apps show one dot on the orb each and one shared list, cleared everywhere at once) + `POST /api/jarvis/push/register` (`{token, platform, environment, bundle, name?}`, same header; Jarvis `/push/register`, so he can send lock-screen pushes to that device),
  `GET /api/jarvis/memory` + `GET /api/jarvis/memory/search?q=` + `POST /api/jarvis/memory` (`{op: remember|forget}`, same header; Jarvis `/memory/facts`, `/memory/search`),
  `GET /api/jarvis/memory/graph` (`{graph}`: `{nodes: [{id, type: person|place|project|routine|preference|plan|loop|other, name, group, facts (a count), links (a count), updated}], links: [{from, to, kind}]}`, null on an older Jarvis; Jarvis `/memory/graph`) + `GET /api/jarvis/memory/node/<id>` (`{node}`: `{id, type, name, aliases, group, facts: [{id, text, source, updated, confidence}], links: [{id, name, type, kind}], loops: [{text, due}]}`; ids are his own paths such as `people/sam` or `loops/book the table`, so percent-encode them (`nodeIdFromPath`); a link's `kind` reads from → to; 400 on an id that can't be read, 404 `{gone: true}` when he no longer has it; Jarvis `/memory/node/{id}`): his memory as a web of linked things for the apps' bubble chart, tap = one node (Dylan 2026-11-26; checks in `server/sources/memory-graph.mjs` `parseGraph`/`parseNode`/`isNodeId`/`nodeIdFromPath`; forgetting a fact is the existing `POST /api/jarvis/memory` `forget` with the fact's id),
  `GET /api/jarvis/playbooks` (`{book: {playbooks, options}}`) + `POST /api/jarvis/playbooks` (`{op: save, playbook}` or `{op: delete|run, id}` or `{op: draft, text}` = Jarvis writes a playbook from a sentence, answered `{ok, playbook}` and not saved (Jarvis `/playbooks/draft`, `fromJarvisDraft`), same header + Tailscale login; Jarvis `GET/POST /playbooks`, `/playbooks/{id}/delete`, `/playbooks/{id}/run` (answers `{ok, detail, checks}`, or `detail: running` after 50 s); checks and snake_case mapping in `server/sources/playbooks.mjs`) (fetched on demand, not in the snapshot). A playbook = name, on/off, what it's for, one trigger (time + days, arrive, leave, asleep, awake, manual) and up to 20 steps (device, scene, app on a TV, notify, `think` = Jarvis does it in words with `model` auto|worker (Ornith)|claude, email, wait, `job` = one of Jarvis's own jobs as plain code, `{type: 'job', job: 'nightly'}`, picked from `options.jobs` `[{id, name}]`; the "Nightly self-improvement" playbook owns the 3:30 AM nightly pass this way, so switching it off or retiming it really moves Nightly, Dylan 2026-11-20; **clients keep no list of step kinds** (Dylan 2026-11-20): Jarvis describes them in `options.step_types` (`server/sources/step-types.mjs parseStepTypes` → `options.stepTypes`: each `{type, label, short, runs: code|thinking, summary: "{entity.name}: {command} {value}", fields: [{key, label, kind: text|longtext|number|bool|choice|emails|by_command, required, min, max, default, choices | choicesFrom: devices|scenes|apps|jobs|thinkers (+ dependsOn, choicesKey = the picked row's sub-list), byCommand, onlyDomains}]}`; `DEFAULT_STEP_TYPES` = the fallback for an older Jarvis and the mock), so a new kind in Jarvis needs no client change; a `PlaybookStep` is just `{type, ...values}`, a kind he doesn't describe is passed through untouched, a pick left to Jarvis (`auto`) is left out on the way to him, addresses are one comma line for clients and a list for him), a **done** checklist Jarvis checks himself against after each run (`lastRun.checks`), plus "More for Jarvis" (when to use, inputs, decisions if/then, edge cases, standard, bad version). What an app saves is `made_by: dylan`, which runs without asking (an email step asks only when `confirm` is true); `madeBy: jarvis` = one he proposed,
  `POST /api/jarvis/reports` (`{op: keep, id, days: 14|30|90}` or `{op: keep, id, keep: true}` = for good / `false` = back to 2 weeks, or `{op: delete, id}`; `parseKeepChoice`, same header + Tailscale login; Jarvis `/reports/{id}/keep`, `/reports/{id}/delete`) + `GET /reports/<id>` (not under `/api/`: one report as its own page, Jarvis's HTML from `GET /reports/{id}` served with `REPORT_CSP` = no scripts, nothing loaded from outside, sandboxed; 404 page when deleted or expired) + snapshot `reports` (Jarvis `GET /reports`, `server/sources/reports.mjs parseReports`: `{reports: [{id, title, summary, created, expires, kept, keepDays, bytes}], totalBytes, keepDays, maxBytes}`; null on an older Jarvis): pages Jarvis writes at the end of a long task, kept 2 weeks unless he picks 1 month, 3 months or forever for one (per-report `keepDays`, null = forever; Dylan 2026-11-19), 200 MB in all; the apps open a report in an in-app view, never a new tab (Dylan 2026-11-18),
  `GET`/`POST /api/jarvis/voice` + `GET /api/jarvis/voice/sample` (WAV; checks in `server/voice.mjs`; Jarvis `/voice`, `/voice/sample`),
  `POST /api/home/control` (`{entity, command, value?}`; climate takes `target` °/`mode`; same header + Tailscale login; allowlist in
  `server/sources/home.mjs`, which also reads devices/weather (with humidity, wind)/sun and read-only sensor `readings` (room temperature/humidity, open doors, motion, low batteries; `toReading`) and the hourly `forecast` (HA `weather.get_forecasts`, 15 min cache, `toForecast`) and `powerWatts` (every power sensor added up) into `snapshot.home`),
  `POST /api/digest/refresh` (same header; asks Jarvis `/digest/refresh`),
  `POST /api/money/picks` (`{op: pick|clear|remind}`, same header; store `server/money-picks.mjs`, file `money-picks-file.mjs`,
  `MONEY_PICKS_FILE`; snapshot `moneyPicks`; banner via `pickReminderDue`).
- **Calories:** snapshot `nutrition` = Jarvis `GET /nutrition/today` (`server/sources/nutrition.mjs parseNutrition`: `{date, eaten, goal, left, burned, protein, proteinGoal, fat, fatGoal, carbs, carbsGoal}` (fat and carbs goals in grams since 2026-11-19, he's cutting; null on an older Jarvis), numbers only; feeds the Watch's Calories left complication). The apps' Diet screen reads `GET /api/jarvis/nutrition/day?date=` (`{day}`: `{date, goals, totals: {…, burned}, items: [{id, at, name, portion, calories, protein, fat, carbs, hasPhoto}]}`, `parseNutritionDay`) and `/week?start=` (`{week}`: `{start, days: [{date, calories, goal, protein, proteinGoal, fat, fatGoal, carbs, carbsGoal}]}`, `parseNutritionWeek`; two rings per day) and `/days?end=&count=` (`{days, earliest}`: up to 14 of the same day objects newest first + the earliest day with anything logged, for the endless food list; `parseNutritionDays`, `dayCount`; Jarvis `/nutrition/days`) and `GET /api/jarvis/nutrition/photo/<id>` (`?size=thumb` for the ~320 px one; the picture's bytes, 404 when the meal has none, `cache-control: private` for a day; `isMealId`, `photoType`; Jarvis `/nutrition/photo/{id}`, location data stripped there): Jarvis `/nutrition/day`, `/nutrition/week` as the caller (Tailscale login); meal names, so never in the snapshot; 400 on a date that isn't `YYYY-MM-DD`.
- **Sleep:** nights from the Apple Watch live in Jarvis's health store (his `/health/sleep`; today the morning Shortcut posts them, the iPhone app's Health reading replaces it). `GET /api/jarvis/health/sleep` (`?night=YYYY-MM-DD` or `?days=` 1-30, default 7; `{nights}` newest first, each `{night (the morning's date, Pacific), bedtime, wake, minutes: {asleep, inBed, awake, deep, rem, core, unspecified}, interruptions (5 min or more), vitals: {heartRate {avg, min}, hrvMs, hrvRmssdMs, respiratoryRate, spo2 {avg, min}, wristTempC, wristTempDeltaC, breathingDisturbances}, score 0-100, scoreSource: jarvis|apple, scoreBand: great 85+|good 70+|fair 50+|poor (`scoreBand`, the same words Jarvis says), scoreParts: {duration /50, consistency /30, interruptions /20}, stages: [{stage: core|deep|rem|awake|unspecified, start, end}]}`; as the caller) + `POST /api/jarvis/health/sleep` (one night from the app in camelCase: `night`, `stages` (1-500), optional `inBedStart/End`, `asleepStart/End`, `heartRate`, `hrvMs`, `hrvRmssdMs`, `respiratoryRate`, `spo2` in percent, `wristTempC`, `breathingDisturbances`, `source`; same header + Tailscale login; a resend replaces the night; 400 with plain words on a bad night, also when Jarvis refuses it; answers `{ok, message, night}`); checks and snake_case mapping in `server/sources/sleep.mjs` (`cleanSleepNight`, `parseSleepNight(s)`, `sleepDayCount`). Snapshot `sleep` = `{last: the latest night without stages, trend: up to 7 of {night, score, asleep}}` (`sleepSummary`; null on an older Jarvis) for the apps' Home card and the TV carousel, which should prefer it over the digest's `cloud.health.sleep`. - **Memory and disks:** snapshot `ram` = `{totalMb, usedMb, scope: pc|linux (what the numbers cover), users: [{name, role, mb}]}` and `disks` = `[{id, name, usedGb, totalGb, users: [{name, gb}]}]`, each biggest first with an "Everything else" row for the unnamed rest, null on an older Jarvis: who is using the PC's memory and its disks, measured by Jarvis (`GET /system`, since the server's container can't see the PC's programs) and checked in `server/sources/system.mjs` (`parseSystem`, `parseRam`, `parseDisks`); for the apps' Memory and Storage panels beside the graphics card ring (Dylan 2026-11-21).

- **Talk:** `server/talk.mjs` proxies the `/api/jarvis/talk` WebSocket (wired in `server/index.mjs`) to Jarvis `/talk/ws?chat=web` (Tailscale login + same-origin `Origin`);

- **Jobs:** snapshot `jobs` (Jarvis `GET /jobs`, `server/sources/jobs.mjs parseJobs`; null on an older Jarvis): `running` = work he sent to the background, each `{id, label, state, startedAt, model, step, stoppable}` (`model` = the raw model name, `step` = one line on where it's at, both null when he doesn't say; Dylan 2026-11-19); `stoppable: true` = it can be stopped with `POST /api/jarvis/jobs/stop` (`{id}`, same header + Tailscale login; Jarvis `/jobs/{id}/stop`; 410 `{ok: false, gone: true, message}` when it already finished, 409 while it's going live; `isJobId`; the apps' full swipe on a running row, Dylan 2026-11-20); `finished` = what ended today `{id, label, state: live|failed|nothing|stopped, finishedAt, model}` (`parseFinished`), plus the scheduled jobs. `snapshot.gpu` = `{totalMb, usedMb, utilization, users: [{name, role, mb, kind: local|speech|other}]}` from `server/sources/gpu.mjs` (nvidia-smi + Ollama `/api/ps` + Jarvis `GET /gpu`; null when nvidia-smi fails).
- **Shell:** `server/shell.mjs` proxies `/shell/` (HTTP + WebSocket upgrade, wired in `server/index.mjs`)
  to ttyd on 127.0.0.1:7681 (`deploy/ttyd.service`, tmux) only for `SHELL_USERS` Tailscale logins with a same-origin `Origin`.
- **Sources:** `server/sources/mock.mjs` (default; Pacific-time schedule, remembers
  the local model loaded/unloaded), `server/sources/live.mjs` (parallel probes, 2.5 s timeouts).
  Picked by `DATA_SOURCE` in `server/app.mjs createSource`.
- **Config/env:** `server/config.mjs` (`loadConfig`, `loadEnvFile`). All vars in `.env.example`.
- **Shape:** the snapshot both sources build (`server/sources/mock.mjs`, `live.mjs`); its Swift side is in `ios/Sources/JarvisKit`. Change it → update BOTH sources.
- **Cloud digest:** `server/sources/digest.mjs` reads `digest.json` from the private
  `DIGEST_REPO` with `DIGEST_TOKEN` (2 min cache; written every 15 min);
  the scheduled task's prompt + setup in `docs/digest.md`.
- **Tests:** `tests/unit/*` (Vitest).
  `tests/unit/helpers.ts callApi` drives the handler without a port.
- **Deploy:** `deploy/home-lab.service` (systemd on jarvis) or `Dockerfile` +
  `docker-compose.yml` (host network, 127.0.0.1:4180, published by `tailscale serve` on https 443), CI in `.github/workflows/ci.yml`
  (its `merge` job rebase-merges a passing non-draft PR into `dev`, then it and
  `promote` fast-forward `main` to `dev`).
